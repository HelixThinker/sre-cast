    A worked example

    Beyond the
    expensive regex.

    Cloudflare’s July 2, 2019 outage shows why an incident review needs more than the component that failed.

    A globally deployed WAF rule exhausted CPU used to serve HTTP traffic. Customers received 502 errors. Restoring traffic and restoring WAF protection were separate milestones.

    14:09 UTCHTTP traffic recovered
    14:52 UTCWAF protection restored
    01
    Reported mechanism

    A nonblocking rule still consumes resources.

    Simulate mode did not block requests, but it still executed the regex. Excessive backtracking exhausted CPU shared with HTTP serving.

    Proposal. Bound rule execution cost and define request handling at that limit. Cloudflare reported restoring a CPU guard by July 12; its existence alone does not show its effectiveness.

    Check. Exercise expensive inputs under load. Observe both HTTP capacity and security behavior when the limit is reached.

    02
    Unknown control

    Could live signals stop expansion?

    The public report establishes rapid global distribution, then alerts and response. It does not establish a signal-to-stop mechanism for this release.

    Next evidence. Inspect rollout configuration and event history. An absent gate needs design; an existing gate needs an explanation of its failure.

    Check. Measure how much traffic is exposed before a stop takes effect. A fast alert after global propagation does not demonstrate containment.

    03
    Reported recovery

    Emergency control must remain usable.

    Responders terminated the WAF globally at 14:07. Access failure and an unfamiliar bypass obstructed response; the exact dependency topology remains unknown.

    Proposal. Provide a practiced emergency command path with usable credentials, confirmation of execution, and a route to restore protection.

    Check. In a controlled exercise with normal authentication unavailable, execute a bounded action, confirm its effect, and restore protection.

    This is our partial analysis of Cloudflare’s July 2 account and July 12 postmortem, not an internal investigation. The full map attaches source passages, findings, and proposals to each relationship.

    Use it on your next incident

    Bring the evidence.
    Leave with a working map.

    SRE CAST combines practical review rules, informed by Nancy Leveson’s CAST handbook, with an incident-map skill. Use the rules alone or give the skill to your agent.

    1. Get the repository and keep the whole skills/incident-map/ folder together.
    2. Give your agent the prompt and an incident report, timeline, or other evidence.
    3. Open the generated HTML. Select a relationship, edit its details, and use Save HTML to keep a new copy.
    Your starting prompt
    Use skills/incident-map/SKILL.md to map this incident: [report URL or file].

Save the interactive map as incident.html. Mark unknown relationships and show which evidence would change the next decision.

    The output is a standalone HTML file. No account or server is needed to use it; following external sources needs internet. Edits stay in the open page until you save a new copy.

    The skill makes the review inspectable and editable. It does not guarantee a better analysis or replace access to incident participants.
